# قوالب بريد سوقك | SOOQAK — لم تُطبق بعد

الموضع: Supabase Dashboard > Authentication > Email Templates.

1. `confirm_signup.html`: قالب Confirm signup — عنوان الرسالة: `تأكيد بريدك الإلكتروني | سوقك | SOOQAK`.
2. `magic_link.html`: قالب Magic Link — عنوان الرسالة: `رابط تسجيل الدخول | سوقك | SOOQAK`.

هذه ملفات جاهزة للمراجعة والنسخ إلى لوحة Supabase. لم تُحدّث إعدادات Supabase خلال V36.
المتغير `{{ .ConfirmationURL }}` يجب أن يبقى كما هو حتى يعمل رابط الدخول؛ لا ترسل محتويات بريد أو رموز حقيقية للاختبار.
تغيير اسم/عنوان **المرسل** نفسه يتطلب إعداد SMTP أو خدمة إرسال موثقة وقد يتطلب نطاقًا، ولم يُنفذ.

3. `recovery.html`: قالب Reset Password — عنوان البريد: `سوقك | تعيين كلمة مرور جديدة`. التصميم عربي RTL، كحلي وذهبي، ويحتفظ بمتغير `{{ .ConfirmationURL }}` الخاص برابط الاستعادة.

## ما يحتاج تفعيلًا في لوحة Supabase (لم يُنفذ على النظام الحي)
1. افتح Authentication → Email Templates → Reset Password، ضع العنوان العربي والصق محتوى `recovery.html` كاملاً ثم احفظه بعد اعتماد المالك.
2. في Authentication → URL Configuration تأكد أن Site URL وRedirect URLs تسمح بعنوان صفحة `/index.html` الخاصة ببيئة التجارب المستقرة، **من دون توسيع السماح إلى كل المواقع**. المعاينات المؤقتة المحمية قد لا تكون مناسبة لروابط البريد.
3. استخدم حساب اختبار مخولًا، اطلب رابط استعادة مرة واحدة، ثم تأكد من وصول قالب «سوقك» وإظهار نموذج «تعيين كلمة مرور جديدة» بعد فتح الرابط، ثم القدرة على الدخول بالكلمة الجديدة.
4. لا تحفظ رموز الوصول ولا روابط البريد الخاصة في GitHub أو Google Drive، ولا تكرر طلبات البريد بكثافة. إذا لم يفتح الرابط فعّل تتبع الخطأ دون كشف الرمز.
5. يبقى اسم مرسل الرسالة الافتراضي Supabase Auth إلى حين إعداد SMTP ونطاق موثق وموافقة التكلفة. تغيير النص وحده لا يغيّر هوية المرسل.

الملف الموجود مسبقًا `recovery.html` **قالب جاهز، وليس رسالة مفعّلة**. عطل الاستعادة المصور من المستخدم لا يُعد محلولًا تشغيليًا حتى ينجح اختبار حقيقي بعد ضبط الإعدادات.
